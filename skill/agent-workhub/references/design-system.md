# Workhub 统一设计规范

**一套视觉，三种内容布局**。项目切换时保留字体、色彩、字号、导航习惯和控件表现；选择模板是选择内容结构，不是选择另一套皮肤。

## 单一来源

设计文件唯一来源：工作台仓库 `static/design-system.css`。全局变量以 `--wh-` 为前缀：

| 要素 | 统一值 |
| --- | --- |
| 页面背景 / 内容表面 | `--wh-bg: #ffffff` / `--wh-surface: #fff` |
| 正文 / 辅助文字 | `--wh-ink: #171717` / `--wh-muted: #666666` |
| 强调色 | `--wh-accent: #171717` |
| 边框 / 圆角 | `--wh-border: #e8e8e8` / `--wh-radius: 10px` |
| 字体 | `--wh-font`：系统无衬线，包括 PingFang SC |
| 字号 | 12px 元信息、13px 辅助正文、14px 正文、16px 内容标题；中控台无重复页面大标题 |
| 间距 | 4 / 8 / 12 / 16 / 24 / 32 / 48px |

正文和辅助文字对浅色背景、白字对主按钮色满足至少 4.5:1 对比。禁止为了轻盈而把主要内容降为难读的浅灰绿。不要为某项目另选字体、紫色/砖红主题、独立圆角或控件尺寸。

门户加载这份 canonical CSS。三个预览模板直接通过门户 `/design-system.css` 和 `/templates/runtime.js` 读取共享资源；生成器会复制当前 canonical CSS 与 JS 到正式站点，并改为相对路径，因此正式网站无需门户端口也能独立显示。`workhub-site.json` 记录 `design_system: workhub-v1` 和主题文件哈希，以便知道网站采用了哪个版本。

## 紧凑中控台标题规则

门户与带侧栏的项目工作台遵循紧凑标题规则：

- 左侧导航已表明页面名称时，内容区不再放重复的大标题、英文口号或宣传式说明横幅。
- 内容从搜索、筛选、项目列表、数据或站点画布开始；顶部常规间距约 14–20px，不留一整块标题占位。
- “接入网站”“接入项目”“评议全部项目”等必要动作放到对应列表或功能卡的紧凑工具栏；删除标题时不删除这些功能。
- 内容分组、文章、项目名称和弹窗中确有用途的标题仍可保留。独立网站没有侧栏页面标题时，可保留一次紧凑的网站身份标题。

门户默认使用紧凑密度：优先减少工具栏高度、页面留白、列表行与卡片的内边距，让项目画布和内容列表获得空间。正文保持 14px、辅助文字约 12px；不通过全局缩放或整体缩小字号来压缩页面。折叠侧栏、网站目录和顶部控件后，画布按实际剩余视口自动扩展，不保留收起前的宽高占位。窄屏允许中英文控件换行并保留可点击面积；紧凑样式只作用于门户，不强制改写内嵌项目的布局和媒体。

已选择网站的项目空间默认以原站正文为主，选择网站或从其他页面返回时自动收起门户控件。恢复箭头放在独立的 18px 顶边带内，不浮盖项目文字；用户展开控件后，不因轮询或 iframe load 再次强制收起。无网站的空态和其他工作台页面保留导航，收起与展开不重载 iframe、不抢项目输入焦点。

## 三种布局的固定分工

- `radar`：同一套统计卡、分类 tabs、条目列表和来源侧栏，用于连续信息收集。
- `library`：同一套搜索与排序控件、分类目录和资料卡，用于积累和检索。
- `brief`：同一套字体和卡片，强调焦点文章、目录和支持发现，用于归纳结论。

标题区、搜索控件、按钮、弹窗、空状态、加载和错误提示的视觉约定不随布局切换。保留键盘焦点、表单标签、Esc 关闭弹窗、窄屏换行和减少动画偏好。

## 项目适配

新建网站应直接用生成器，并复用统一组件；布局可按内容调整，视觉 token 保持固定。正式站默认不带演示条目，网站内容由项目自身 `data.json` 提供。

已有静态网站可以由门户目录服务在响应层加载统一阅读主题，源文件仍保留；模板新站直接使用原生设计系统。需要细化旧站适配时，先检查对现有布局和交互的影响，按项目渐进调整，不直接批量改写所有项目。动态应用由自身加载同一主题或采用这些 token；不尝试从跨源 iframe 操作其 DOM，也不通过修改浏览器保护来强迫注入。

后续维护主题时修改 canonical 源文件；新生成网站会获得新版本。已有正式站持有独立快照，需要在该项目中明确更新主题文件，不能把“生成成功”误报为所有历史站点已迁移。

## 门户与项目页面同步配色

配色是整个工作空间的选择，不能只改变门户边框。可用颜色以 canonical CSS、`static/theme.js` 的枚举为准；扩充配色时同步模板与嵌入运行时，保留同一套布局和字号。门户收起时，项目画布使用实际剩余窗口空间，不锁住收起前的像素宽高。

目录网站由门户注入固定的 `/__workhub/theme.css` 和 `/__workhub/theme.js`，保留 `workhub_theme=original` 的原样预览入口。独立后端站点在自己的 HTML 中引入门户的 `/design-system.css`、`/embedded-theme.css` 和 `/embedded-theme.js`；有严格 CSP 的站点可发布同源资源快照，不能靠通用代理或跨域读取 DOM 改色。

已有复杂应用使用 `body[data-workhub-native]`，由本地适配 CSS 把原有颜色变量映射到 `--wh-*`；通用嵌入样式跳过原生应用的强覆盖。只改界面颜色，保留布局、字体大小、滚动、表单草稿、PDF/视频图像及风险/成功等语义状态色。

子页接收 `{type: 'workhub:theme', theme}`，并通过 `workhub:theme-request` / `workhub:theme-ready` 向父页请求当前配色。默认只接受真正父窗口的 `http://127.0.0.1:8787` 来源；其他本机端口须在页面明确设置 `data-workhub-parent-origin`，不能把任意 referrer 当成授权。父页只回复当前登记 iframe 的实际窗口与精确 HTTP(S) 来源，不用 `*`。

验收至少切换两种颜色，核对项目正文、工具栏、面板和主要按钮实际跟随，并确认未导航 iframe、未丢失筛选或输入。只证明门户的选择器变了，或只收到消息，不能称项目配色已接通；未完成浏览器视觉核验时如实说明。

## 双语一致性 / Bilingual consistency

- 简体中文与 English 使用同一视觉 token、导航结构与控件尺寸；翻译不是重新设计各站的理由。
- 语言选择位于紧凑顶部工具栏，在当前来源的浏览器本地持久化；刷新后恢复，切换不重置当前页面、站点、筛选或表单草稿。
- 支持协议的模板接收门户语言选择并更新界面；不改变第三方网站 URL 或试图跨源修改其 DOM。
- 翻译固定界面文字、状态和维度名称、空状态、加载和错误提示；保留项目名称、来源内容、记录与已有评议的原文，不触发机器翻译或新模型请求。
- 检查英文长标签、窄屏、键盘焦点和表单标签。左侧已显示页面标题时，两种语言均不增加重复大页头或顶部占位。

Both languages share the same visual system. Save the language preference without losing navigation or input state. Translate UI chrome, not stored project content, and keep the sidebar-first title rule in both languages. Documentation must provide reciprocal language links and describe the same technical and privacy boundaries.


## Codex 外观与文章阅读

默认 codex-light 为纯白界面，codex-dark 为中性深色；原有八种浅色配色继续兼容。主题枚举由 static/theme.js 提供，模板在首屏 CSS 前加载同一脚本；生成器需同时复制 theme.js。
文章用 meta[name="workhub-reading-theme"][content="light"] 或 html[data-workhub-reading-theme="light"] 显式固定明亮。嵌入运行时尊重这一局部声明且不改写保存的工作空间偏好。通用主题注入不改变字体、排版、内容或媒体。
复用示例：examples/reading-light/index.html 与 markdown-light.css。公众号粘贴版仍使用全内联白名单 HTML，不能把本地预览的 style/class 当作微信兼容产物。
