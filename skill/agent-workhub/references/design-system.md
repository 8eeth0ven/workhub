# Workhub 统一设计规范

**一套视觉，三种内容布局**。项目切换时保留字体、色彩、字号、导航习惯和控件表现；选择模板是选择内容结构，不是选择另一套皮肤。

## 单一来源

设计文件唯一来源：工作台仓库 `static/design-system.css`。全局变量以 `--wh-` 为前缀：

| 要素 | 统一值 |
| --- | --- |
| 页面背景 / 内容表面 | `--wh-bg: #f7f8f4` / `--wh-surface: #fff` |
| 正文 / 辅助文字 | `--wh-ink: #252b26` / `--wh-muted: #687267` |
| 强调色 | `--wh-accent: #53634d` |
| 边框 / 圆角 | `--wh-border: #e1e5dc` / `--wh-radius: 10px` |
| 字体 | `--wh-font`：系统无衬线，包括 PingFang SC |
| 字号 | 12px 元信息、13px 辅助正文、14px 正文、16px 内容标题；中控台无重复页面大标题 |
| 间距 | 4 / 8 / 12 / 16 / 24 / 32 / 48px |

正文和辅助文字对浅色背景、白字对主按钮色满足至少 4.5:1 对比。禁止为了轻盈而把主要内容降为难读的浅灰绿。不要为某项目另选字体、紫色/砖红主题、独立圆角或控件尺寸。

门户加载这份 canonical CSS。三个预览模板直接通过门户 `/design-system.css` 和 `/templates/runtime.js` 读取共享资源；生成器会复制当前 canonical CSS 与 JS 到正式站点，并改为相对路径，因此正式网站无需门户端口也能独立显示。`workhub-site.json` 记录 `design_system: workhub-v1` 和主题文件哈希，以便知道网站采用了哪个版本。

## 紧凑中控台标题规则

门户与带侧栏的项目工作台遵循紧凑标题规则：

- 左侧导航已表明页面名称时，内容区不再放重复的大标题、英文口号或宣传式说明横幅。
- 内容从搜索、筛选、项目列表、数据或站点画布开始；顶部常规间距约 14–20px，不留一整块标题占位。
- “接入网站”“接入项目”“评议全部项目”等必要动作放到对应列表或功能卡的紧凑工具栏；删除标题时不删除这些功能。
- 内容分组、文章、项目名称和弹窗中确有用途的标题仍可保留。独立网站没有侧栏页面标题时，可保留一次紧凑的网站身份标题。

## 三种布局的固定分工

- `radar`：同一套统计卡、分类 tabs、条目列表和来源侧栏，用于连续信息收集。
- `library`：同一套搜索与排序控件、分类目录和资料卡，用于积累和检索。
- `brief`：同一套字体和卡片，强调焦点文章、目录和支持发现，用于归纳结论。

标题区、搜索控件、按钮、弹窗、空状态、加载和错误提示的视觉约定不随布局切换。保留键盘焦点、表单标签、Esc 关闭弹窗、窄屏换行和减少动画偏好。

## 项目适配

新建网站应直接用生成器，并复用统一组件；布局可按内容调整，视觉 token 保持固定。正式站默认不带演示条目，网站内容由项目自身 `data.json` 提供。

已有静态网站可以由门户目录服务在响应层加载统一阅读主题，源文件仍保留；模板新站直接使用原生设计系统。需要细化旧站适配时，先检查对现有布局和交互的影响，按项目渐进调整，不直接批量改写所有项目。动态应用由自身加载同一主题或采用这些 token；不尝试从跨源 iframe 操作其 DOM，也不通过修改浏览器保护来强迫注入。

后续维护主题时修改 canonical 源文件；新生成网站会获得新版本。已有正式站持有独立快照，需要在该项目中明确更新主题文件，不能把“生成成功”误报为所有历史站点已迁移。
