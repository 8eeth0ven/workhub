# 中控台项目评议

评议通过用户配置的模型检查已登记项目资料是否足以支撑当前决策。它是项目工作的第二视角，不替代代码测试、实验、人工判断或业务验收。评价对象是当前证据支持的目标与推进状态；不能用项目名称推断项目优劣。

## 六类追问

每次最多提出六个有针对性的问题；项目已有答案时继续追问其证据与边界，避免重复通用问题。

1. **澄清目标**：要解决谁的什么问题？怎样算完成？
2. **检查假设**：哪些前提尚未证实？前提失败时方案还成立吗？
3. **审查证据**：结论来自什么观察或验证？证据支持到哪一步？
4. **替代视角与反例**：有没有更简单的解释、相反情况、遗漏的使用者或失败路径？
5. **后果与取舍**：决定会带来什么后果？成功、失败和不行动分别意味着什么？
6. **反思问题本身**：当前提问是否过窄？还缺哪些信息才能做下一步决定？

每个问题附“为什么问”和“怎样验证”，优先下一步能够实际执行的检查。风险和盲点只有来源支持时才能作为发现；没有证据的内容应表达为待核实的假设或问题。

## 深度评议的闭环

深度由证据和可执行的验证来衡量，不由字数、模型名称或一次调用成功来衡量：

1. **具体主张**：明确项目声称解决什么、适用范围和完成条件。
2. **原始依据**：为主张关联可追溯的记录、产物、原始来源或实验；区分观察事实与推断。
3. **反例与缺口**：主动寻找反证、未覆盖对象、替代解释及证据不能支持的部分。没有发现反例不等于已经证实主张。
4. **验证动作**：把未决问题变成可执行的检查，写明输入、预期观察和何时能判定失败；实际完成后再记录结果。
5. **再评议**：使用新增证据检查原结论是否仍成立，保留旧版本及变化理由，不把旧建议复述成新的验证结果。

无法判断时保留未评分与所缺资料。模型成功调用不等于项目验收通过；归档了文章、图片或测试报告也不等于其主张已被验证或文章已在平台发布。

## 五个评价维度

目标清晰度、证据质量、验证覆盖、风险与盲点、下一步明确性。每维采用 0–4 或“暂无法判断”，给出依据与证据编号。没有资料不等于 0 分；资料不足时全部评分留空，并明确补充内容。

展示最近评价的时间、模型、证据数量与置信度。新工作记录或用户补充出现后，旧评价应标记过期；保留历史版本。不能把模型的评价当成已经完成了其建议的验证。

## 使用入口与数据

门户的“项目评议”支持单项目、全部项目、回答追问后继续评议。Agent 可运行以下命令；从项目根目录发起时使用其真实绝对路径：

```sh
"$HOME/.local/bin/agent-workhub" review --project "$PWD"
```

用户启用评议后，在重要里程碑已经记录后发起一次评议，并将需要实际处理的问题纳入下一步工作。相同证据可复用已有评价；只有需要明确重新判断时才强制刷新。不要在每次工具调用后反复调用模型。调用失败应报告失败，不能以本地模板结果冒充模型评价。

只有本机后端读取密钥。私有配置默认 `~/.local/share/agent-workhub/llm.json`，权限为 `0600`；仅在其不存在时回退读取旧 `glm.json`，两份配置不会混合。通用环境变量为 `WORKHUB_LLM_PROVIDER`、`WORKHUB_LLM_API_KEYS`（或单个 `WORKHUB_LLM_API_KEY`）、`WORKHUB_LLM_BASE_URL`、`WORKHUB_LLM_MODEL`。`GLM_*` 仅对 GLM 提供者兼容回退。完整配置例子见仓库 `examples/` 和 [安装说明](../../../docs/installation.md)。禁止将密钥写入仓库、命令参数、工作记录、日志、前端代码或 API 响应。

评议会将必要的项目名、简介、近期工作摘要和用户主动补充发送到配置的云端 API、本机模型或 CLI；选择本机模型并不保证其外部依赖不会联网，需要遵守所选工具的实际行为。发送前清除已知凭据等敏感值；不自动读取完整仓库、完整对话或私有环境文件。项目评议基于已登记的有限资料，不把自动脱敏当成所有敏感内容均已移除的保证。

项目档案中的原始提示词和本地文件内容不会因存在于档案就默认发送给评议器。需要用其中的内容支撑评议时，先选择必要、适合交给该评议器的摘要，注明来源和边界；用户主动提供补充背景也应遵循同样的隐私范围。见 [项目档案协议](project-archive.md)。

本地用户可在「项目评议 → 模型接入」选择 API 或已安装的 Codex、Claude Code、Z Code；高级自定义 CLI 仍使用明确保存的参数数组，不经过 shell。保存与连接测试分开，接口不回显密钥，测试不发送项目或会话资料。用户未选择其他提供方时不自动切换或复制凭据；克隆、启动和页面轮询不会自行调用模型。


## 资料不足时补充会话

在用户已启用会话补证的本机协议中，发起评议时可按本项目已关联会话和精确工作目录有界查找 JSONL。只取必要的用户任务与助手最终结果片段，排除系统指令、内部分析、工具原始输出及注入块；共享会话用本项目任务窗口和逐轮目录核对，无法确认归属则跳过。每次最多 3 个会话、约 6500 字符，脱敏并保留会话与行号或字节位置、哈希、截断标记。

片段是会话陈述，不是独立验收。摘要缓存只存本机数据库，页面 GET 不重新读取日志；原始完整聊天不外发。若初次模型仍判资料不足，且确实找到新的对应片段，可由同一提供方最多再评议一次，无新增资料则停止并保留未知。可通过 WORKHUB_SESSION_CONTEXT=off 关闭补证。
